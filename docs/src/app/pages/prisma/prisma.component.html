Prisma 7 Multi-Tenancy

A comprehensive guide to building fully isolated multi-tenant applications using Prisma 7 Client Extensions with automatic tenant filtering.

🔒 Complete Isolation ⚡ Type-Safe 🚀 Cached Clients
✨

Why Prisma Extensions?

Unlike middleware, Prisma Client Extensions provide type-safe query modifications, better performance through caching, and cleaner separation of concerns. This is the recommended approach for Prisma 7+.

1

Define Your Prisma Schema

Set up your database schema with tenant relationships. Every tenant-scoped model should have a tenantId field with appropriate indexes for query performance.

Key Points:

  • • @@index([tenantId]) on every tenant-scoped model for fast queries
  • • @@unique([tenantId, email]) for tenant-scoped uniqueness
  • • onDelete: Cascade to clean up data when tenant is deleted
2

Create the Tenant Extension

Create a Prisma extension that automatically injects tenantId into all queries. This ensures complete tenant isolation at the database level.

3

Create the Tenant-Aware Prisma Service

Wrap the Prisma client in a service that automatically applies the tenant extension based on the current request context. Extended clients are cached per tenant for performance.

4

Create the Prisma Module

Export the service globally so it can be injected anywhere in your application.

5

Configure the App Module

Wire everything together with the multi-tenant module and a database-backed tenant resolver.

6

Use in Your Services

Your services can now use the tenant-scoped Prisma client. All queries automatically filter by the current tenant—no need to manually add tenantId to every query.

7

Create Your Controller

Use the decorators from @lexmata/nestjs-multi-tenant to access tenant information and protect routes.

Alternative: Prisma Middleware Approach

For simpler use cases, you can use Prisma middleware instead of extensions. This approach is less type-safe but requires less boilerplate code.

⚠️ Middleware Limitations

  • • Less type-safe than extensions
  • • Middleware is deprecated in Prisma 7 (use extensions instead)
  • • Cannot cache extended clients efficiently

Key Benefits

🔒

Complete Isolation

Tenant data cannot leak between requests. Every query is automatically scoped.

🤖

Automatic Filtering

No need to remember to add tenantId to every query. It's injected automatically.

📝

Type Safety

Full TypeScript support with Prisma's generated types and IntelliSense.

⚡

Performance

Client caching prevents extension recreation per request.

🚪

Escape Hatch

baseClientUnscoped for cross-tenant admin operations.

🧪

Testable

Easy to mock tenant context in unit tests with clearCache().
